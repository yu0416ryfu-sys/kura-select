  KuraSelect の記事の入れ替え（試し記事を出し、集客の取れない記事を noindex で外す）を一連で回すスキル。
  「記事の入れ替えをして」「入れ替えを回して」「月次の入れ替え」「入れ替えた記事の2週判定をして」などと頼まれた場合に使う。
  判定待ちの新規記事の判定（7日の早期判定・2週判定）→ 外す記事の選定（pnpm rotation:candidates・M0〜M4）→ 枠の計算 →
  テーマ選定（kura-article-recommend）→ 承認 → 執筆（kura-article-create）→ 公開の承認 → 記録と教訓の追記までを行う。
  新規記事の候補出しだけなら kura-article-recommend、記事の作成だけなら kura-article-create、
  既存記事の加筆は kura-content-improve、未登録の記事は kura-index-recover を使う。

# KuraSelect 記事の入れ替えスキル

集客の取れない記事を noindex で外し、同じ本数だけ新しい題材を試す。当たった記事は育て、外れた記事は60日後の月次で外す。
ルール（1対1・月10本・M0〜M4・採択基準・試験枠）は `docs/IMPLEMENTATION_PLAN_ARTICLE_ROTATION_2026-10-13.md` とメモリ `feedback_article_rotation` が正。このスキルはそれを変えず、順番・止まる場所・記録だけを決める。

## 0. 原則

- 手順を複製しない。テーマ選定は `kura-article-recommend`、執筆と事実の照合は `kura-article-create` の本文に従う
- 外すのは noindex（`data/noindex-articles.json` に1行足す）。記事ファイルは消さない
- ユーザーに諮る関門は2つ（§6・§8）。関門の外でコミット・push しない
- 基準を自分で変えない。教訓は `docs/ROTATION_LESSONS.md` に追記し、見直しは §10 で提案だけする
- noindex にした記事の解除を提案しない（ユーザーが言い出したときだけ行い、外した本数から1を引く）
- `docs/` が無い環境（別 PC）では止まる（枠と判定待ちが読めない）

## 1. 準備

1. `git status` が clean か確かめる。clean でなければ止めて伝える
2. `grep -n "禁止日" docs/TODO.md` と `data/measurement-holds.json`（`releaseDate > 今日`）を見る。公開予定日が禁止日なら日をずらす案を §6 で出す
3. Google 検索ステータス: `data/google-search-status.json` の `updatedAt` が7日より古ければ、まず `pnpm search-status -- --window=今日:今日`（`--offline` なし）で取り直す。ファイルが変わっても、ここではコミットせず作業ツリーに残す（コミットは §8 で、記事・noindex と分けた1コミットにする。§1-1 の clean の確認はこの取り直しより前に行う）。7日以内なら `--offline` を付ける。どちらでも、取得日を §6 で伝える。コアアップデートの影響期間なら、新規記事の公開と入れ替えの noindex は進めてよいが、2週判定は暫定になることを §6 で伝える（CLAUDE.md §5.0.2 ルール6）。既存記事の前後比較の施策はこのスキルで打たない
4. `docs/ROTATION_LOG.md`（累計・月の公開本数・判定待ち）と `docs/ROTATION_LESSONS.md` を読む

## 2. 判定待ちの新規記事の判定（7日の早期判定・2週判定）

`docs/ROTATION_LOG.md` の新規記事の表で、「2週後の順位帯」が「MM-DD 早期判定」または「MM-DD 判定」のままで、その日付が今日以前の行を判定する。

**「2週判定だけ」「早期判定だけ」と頼まれたとき**（TODO の判定の行から入ったとき）は、§1 → §2 → §6 のうち判定の案の提示と承認後の記入 → §8（判定に伴うコミットだけ）で終え、§3〜§5・§7 は行わない。

**7日の早期判定（2026-11-21 ユーザー決定）**: 離陸した記事は5〜7日目に順位帯がほぼ決まる（lip-balm は初日から6〜8位、baby-formula は5日目から7〜8位で固定）。そこで公開7日で一度判定し、離陸していれば2週を待たずに凍結を解除して育成（加筆・title の調整・他記事からの内部リンク）に移す。

- 窓は公開日〜公開日＋6日。確定日が公開日＋6日に届いていなければ判定しない（GSC の遅れで、届くのは公開日＋9日ごろ）
- 下の 2〜5 と同じ測り方で、区分が「✅離陸」または「✅離陸（Bing）」なら早期判定で確定する（2週判定は行わない）。承認後の記入（§6）で、凍結台帳の `releaseDate` をその日（今日）にして解除し、メモリ `project_measurement_holds` の該当行に「早期判定で解除」と書く
- 「✅離陸」でなければ確定させず、そのまま2週判定（公開日＋16日〜）を待つ（外れの記事は公開60日まで外せないので、7日で急いで確定させる意味がない。試験枠の ❌ は §3 の28日の条件で早く外せる）
- 変動期の早期判定も2週判定と同じく「⚠️暫定」を付ける（解除はしてよい。確定は影響期間の外で取り直す）

**2週判定**:

1. GSC の確定日を `dimensions:["date"]`（直近10日）で実測する。確定日が「公開日＋13日」に届いていなければ、その記事は判定しない（次回に回す）
2. `gsc_search_analytics` を `filterPage`（その記事の URL）・`dimensions:["query"]`・公開日〜公開日＋13日（早期判定では＋6日）で取る。テーマ語（採択時に測った語と表記ゆれ）を含むクエリの表示加重平均順位を順位帯とする
3. `bing_page_query_stats` でその記事の Bing のクエリを取る
4. 区分（2026-11-21 ユーザー決定）: テーマ語のクエリの順位帯が 1〜10 位なら「✅離陸」、11〜20 位なら「△境界」、21 位以下かテーマ語のクエリが0行なら「❌未離陸」。Google が未離陸でも Bing のテーマ語で10位以内の表示があれば「✅離陸（Bing）」。この区分は 2026-11-21 より後の判定から使い、それより前の判定は書き換えない
5. `pnpm search-status -- --offline --window=公開日:公開日＋13日`（保存分は §1-3 で新しくしてある）が「暫定」なら「⚠️暫定（影響期間の外で取り直して確定）」を付ける
6. ここではまだ記入しない。判定の案を §6 で示し、ユーザーが認めた判定だけを §9 で記入する（施策の成否をエージェントが独自に確定しない。AGENTS.md と同じ扱い）

## 3. 外す記事の選定

1. `pnpm rotation:candidates` を実行し、`reports/rotation/candidates-<確定日>.md` を読む。試験枠で2週判定が ❌（暫定でない）の記事は、公開60日を待たず**公開28日から**対象に入る（`docs/ROTATION_LOG.md` の新規記事の表を CLI が読む・2026-11-21 ユーザー決定）。暫定の ❌ は取り直して確定するまで60日のまま
2. `M4` の行が noindex 候補。`hold` の行は理由（取得失敗・改善ログなし）を §6 で伝え、noindex に回さない
3. `M2-hold`（Bing 行なし）の行は、前回の月次でも行なしだった記事に限り、その行の `verdictIfBingZero`（表示0とみなした判定）を使ってよい（2回続けて行なしなら表示0とみなす）。1回目は保留。「前回も行なし」は、前回の `reports/rotation/candidates-*.json` の `bing` が `'行なし'` か、`docs/ROTATION_LOG.md` に「Bing 行なしで M2 判定保留」と記録があること（CLI 導入前の 11-02・11-21 の回は ROTATION_LOG の記録で数える）
4. 季節品（`M3`）は、`data/rotation-seasonal.json` の外す判断の月に当たるときだけ、入れ替え計画書 §2.2 の季節品の手順で判断する。季節品の noindex は §6 で必ずユーザーに確かめる

## 4. 枠の計算

月の枠 ＝ min(10 − その月に公開済みの本数, 累計で外した本数 ＋ 今回 noindex にする本数 − 累計の新規本数)。数字は `docs/ROTATION_LOG.md` の累計の行から取る。枠が0なら §5 を飛ばし、§2・§3 の結果と noindex の候補だけを §6 に出す。

## 5. テーマ選定

`kura-article-recommend` を呼び、その本文の手順で候補を出す。渡すのは「今回の枠」と「`docs/ROTATION_LESSONS.md` を読むこと」。1回に出す本数は min(5, 枠)（試験枠の月の上限は 2026-11-22 に撤廃。本線を通った候補で先に枠を使い、残りを試験枠の5条件を満たす候補で出す。条件を満たす候補が足りなければそこで止める）。ユーザーが本数を指定したときは 5 をその本数に置き換える。

## 6. 関門1（外す記事 × 新しいテーマ）

次をまとめて示し、ユーザーが選んだ分だけ進む。

- §2 の判定の案（区分・数字・暫定かどうか）
- noindex の候補と理由（`reports/rotation/` の行）、保留にした行と理由
- Google 検索ステータスの取得日（§1-3）と、取り直したかどうか
- 枠の計算
- 新しいテーマの候補（本線か試験枠か・採択の根拠・期待送客）
- コアアップデートの影響期間かどうか、公開予定日と禁止日の確認結果

承認されたら、執筆の前に次を記入する。

- 認められた §2 の判定: `docs/ROTATION_LOG.md` の行（確定日・窓・表示・クリック・順位・Bing）。凍結台帳の行の扱いはこれまでの判定と同じ（判定を書き、解除日を過ぎた行は `docs/MEASUREMENT_HOLDS_ARCHIVE.md` へ移す）。暫定なら `docs/TODO.md` §3 に取り直しの行（影響期間の終わりの翌日以降）。`docs/ROTATION_LESSONS.md` に「判定」の行を1本ずつ
- 承認されたテーマ: `docs/ROTATION_LESSONS.md` に「選定」の行（なぜ当たると見たか）

## 7. 執筆と noindex

1. 承認されたテーマを、`kura-article-create` で1本ずつ作る。1本の調査・執筆・事実の照合（同スキルの Step 8 のとおり別担当）を終えてから次の記事に進み、並行して書かない
2. 承認された noindex を `data/noindex-articles.json` に足す（`reason` は「記事の入れ替え M4（GSC 28日表示 N・Bing 4週表示 N・送客0）」の形、`date` は今日）
3. `pnpm test` と `pnpm build`（`check-noindex-dist` が noindex と sitemap の整合を見る）を通す

## 8. 関門2（公開）

記事ごとの疑問リストと H2 の対応、事実の照合で直した点、localhost の 375px 表示の確認結果、コミットの単位（§1-3 で取り直した Google 検索ステータスがあればそれで1コミット、§6 で記入した判定に伴う `data/measurement-holds.json` の変更で1コミット、noindex で1コミット、記事は1本1コミットで新規記事の凍結台帳への記帳はその記事のコミットに含める）を示し、承認を得てからコミット → push する。push 後は `gh run` で deploy の成功を確かめ、本番は変更したページだけを開いて確かめる（多数のページを開かない）。

## 9. 記録

- `docs/ROTATION_LOG.md`: 新規記事の行（公開日・型・採択時の表示と測ったクエリ・「MM-DD 早期判定」＝公開日＋9日）、外した記事の行（実施日・区分・数字）、累計の行と月の行。早期判定で離陸しなかった記事は、その記入のときに「MM-DD 判定」（公開日＋16日）に書き換える
- 凍結台帳: `kura-article-create` の「公開後」のとおり両方に記帳する（`releaseDate` は2週判定の翌日のまま。早期判定で離陸したらその日に早める）
- `docs/TODO.md` §3: 日付欄を「公開日＋9日〜」（`MM-DD〜`）にして「`<slug>` の7日の早期判定（入れ替えスキル §2・「早期判定だけ」で回す。離陸しなければ公開日＋16日〜に2週判定）」の行。GSC の確定日は T-2〜3 なので、公開日＋9日で §2 の条件（確定日が公開日＋6日に届く）を満たす。2週判定に回したら、日付を「公開日＋16日〜」に書き換える
- `docs/ROTATION_LOG.md` の「次回の月次回への持ち越し」: 今回 `M2-hold`（Bing 行なし）だった記事を「`<slug>` は Bing 行なしで M2 判定保留（YYYY-MM-DD）」の形で書く（次の回の §3-3 の「前回も行なし」の根拠。`reports/` は gitignore 済みで別 PC に無いことがあるため）
- `docs/ROTATION_LESSONS.md`: 次の書式で追記する。既存の行は書き換えない

| 日付 | 種類 | 記事 | 内容 | 根拠 |
|---|---|---|---|---|
| YYYY-MM-DD | 選定 / 判定 / 見直し | slug | 選定＝当たると見た理由／判定＝結果と、一般化できること（無ければ「なし」）／見直し＝変えたこと・変えなかったこと | 測ったクエリ・数字・ROTATION_LOG の行 |

## 10. 基準の見直し（提案だけ）

試験枠の2週判定が、前回の見直しから6本たまったら（`docs/ROTATION_LOG.md` の型の欄「（試験枠）」で数える）、本線と試験枠の打率と `docs/ROTATION_LESSONS.md` をまとめ、基準の変更案を最大3つ示して止まる。打率は、2週判定の区分を決めた 2026-11-21（§2-4）までの判定と、それより後の判定を分けて数える（定義が違うものを混ぜない）。変えるのはユーザーが承認した分だけで、変更先は `kura-article-recommend`（両ディレクトリ）・入れ替え計画書・メモリ `feedback_article_rotation`。結果は「見直し」の行に書く。

## 禁止

- 記事ファイルを削除する・凍結中の記事に触れる
- 季節品をユーザーの確認なしに noindex にする
- 関門の承認なしにコミット・push する
- 採択基準・M0〜M4・試験枠の条件を自分で変える
- 取得できなかったデータを0として扱って M4 にする
- noindex 済みの記事の解除を提案する
